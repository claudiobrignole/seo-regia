Tool access / use

The tool is named Regia SEO. It is a private control panel for one operator (Claudio Brignole).

  • Access: a single shared password and a signed session cookie. There are no public sign-ups, no customer tenants, and no external users.
  • No agency, freelancer, or third party can log in. Reports are not sent to an external agency.
  • The Google Ads part of the panel is read-only. The operator views campaign performance and can prepare a draft of a future campaign (text, keywords, suggested daily budget). Drafts stay inside the panel. The operator then creates or edits the live campaign by hand in the Google Ads web interface.
  • The tool does not create, pause, enable, or mutate campaigns, ads, budgets, or keywords through the API.
  • A nightly scheduled job (once per day) pulls the last days of performance into our own database so the dashboard can load without calling the API on every page view.

This application is for Basic Access on production accounts owned by Brignole. We do not need Standard Access or Required Minimum Functionality, because the tool is not offered to external advertisers.

Tool design

High-level flow:

  1. A scheduled job authenticates as a Google Cloud service account that has been invited to the Brignole Google Ads manager / client account.
  2. The job calls GoogleAdsService.Search (GAQL) against the Brignole client customer ID only.
  3. Results are stored in our MySQL database (campaign list, daily metrics, keyword-level metrics).
  4. The web UI at https://seo.brignole.ch/pubblicita/brignole reads that database and shows a table of campaigns (name, status, clicks, spend, a short written recommendation).
  5. Recommendations are computed locally (for example: spend with almost no conversions). They are advice for the operator. They do not write back to Google Ads.
  6. Campaign drafts are stored only in our database. Publishing a live campaign is a manual step in Google Ads, not an API mutate.

Expected API volume: a few Search requests per night (campaign list, campaign metrics by day, keyword_view by day). Well below Basic Access limits. No user-facing live polling of the API.

Authentication: service account (Google Cloud) plus this developer token. The token will be sent only from our hosted panel (Hostinger). It will not be embedded in a public website or a mobile app.

API services called

Read-only. We use the Google Ads API REST method:

  • GoogleAdsService.Search (POST .../customers/{customer_id}/googleAds:search)

GAQL resources and fields:

  • campaign — id, name, status; campaign_budget.amount_micros
  • campaign with segments.date and metrics: impressions, clicks, cost_micros, conversions, ctr, average_cpc
  • keyword_view — ad_group_criterion.keyword.text, segments.date, impressions, clicks, cost_micros, conversions

We do not call mutate methods, including but not limited to:

  • CampaignService / CampaignBudgetService / AdGroupService / AdGroupAdService mutate
  • KeywordPlanIdeaService (not used today)
  • any upload, experiment, or conversion-adjust service

If we later need write access or Keyword Planner, we will submit an updated use description before changing the tool.
